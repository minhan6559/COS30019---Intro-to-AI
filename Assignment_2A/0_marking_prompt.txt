============================================================
CRITICAL TIE-BREAKING REQUIREMENT
============================================================

The assignment specification states that when all else is equal, nodes must be expanded in ascending node number order. For example, if node 4 and node 7 are equally valid candidates, node 4 must be expanded before node 7.

The assignment also states that if two nodes are on different branches of the search tree and are otherwise equal, chronological order must be used: the node added earlier to the frontier must be expanded earlier.

This means tie-breaking has two layers:

1. Local child ordering:
   - When expanding a node, its children/successors should be considered in ascending node number order.
   - Example: if node 2 has children [5, 3, 1], the algorithm should treat them as [1, 3, 5].

2. Frontier tie-breaking:
   - If two or more frontier nodes have the same priority, depth, cost, or heuristic value, the earlier-added node should be expanded first.
   - This is especially important for BFS, GBFS, A*, UCS-style searches, and custom informed searches.

Tie-breaking is important because it affects:
- which goal is reached first when there are multiple destinations,
- which path is returned,
- whether DFS/BFS/GBFS/A* match the expected behaviour,
- whether the implementation is deterministic.

For this marking task, do not focus heavily on the exact node count. The node count is not important. Prioritise:
- correct search strategy,
- correct goal/path behaviour,
- correct tie-breaking,
- correct command-line operation,
- clean and consistent code structure.

============================================================
COMMON TIE-BREAKING MISTAKES TO CHECK
============================================================

Look for these problems in the student code:

- Children are taken directly from a dictionary without sorting.
- Children are taken from a `set`, which gives unstable/unordered behaviour.
- DFS sorts children ascending but pushes them directly onto a stack, causing reverse expansion.
- DFS is recursive and depends on recursion order rather than explicit stack control.
- BFS appends neighbours in whatever order they appear in the file or dictionary, without enforcing ascending order.
- Priority queue entries do not include a stable insertion counter.
- Priority queue tie-breaking uses node object comparison, which may crash or behave inconsistently.
- Priority queue tie-breaking uses only `(priority, node_id)` and ignores chronological order across branches.
- Multiple destination nodes are handled by selecting the smallest destination manually instead of letting the search strategy reach the first valid destination naturally.
- The algorithm checks for goal nodes at the wrong time in a way that changes the expected path.
- Algorithms return the correct path on simple tests but fail on tie cases where equal-cost/equal-priority nodes exist.

Tie-breaking deduction:
- If the algorithm mostly works but tie-breaking is incorrect: deduct 2 marks for that algorithm.
- If wrong tie-breaking only affects edge cases, mention it clearly and apply the standard -2 deduction rather than being harsher.
- If wrong tie-breaking causes the algorithm to behave like a different search strategy or consistently return the wrong goal/path, consider a larger deduction and explain why.
- If the algorithm is fundamentally broken, does not run, gives no valid result, or can enter an infinite loop: 0/10.
